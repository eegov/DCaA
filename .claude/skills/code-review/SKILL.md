# Ревью в чистом контексте

Зачем: агент, который писал код, помнит причины каждого решения и не видит проблем. Субагент `reviewer`
стартует без этой истории. Отчёт ревью обязателен: без него git-хук `pre-merge-commit` не даст влить ветку в dev.

## Порядок
1. Проверь, что `./mvnw verify` проходит. Ревьюить падающий код бессмысленно.
2. Запусти субагента `reviewer` в режиме «ревью». Передай: имя ветки и путь отчёта
   `docs/reviews/<ветка, где / заменён на ->.md`, номер раунда.
3. Исправь все blocker и major. С minor реши сам и запиши решение в отчёт строкой «не исправлено, потому что ...».
4. Повторяй шаги 2–3, пока нет blocker и major, но не больше трёх раундов.
   Если после третьего раунда они остались, остановись и покажи отчёт пользователю: возможно, задача переусложнена.
5. Запусти `reviewer` в режиме «схлопывание» и убери то, что он нашёл лишним. Снова `./mvnw verify`.
6. Закоммить отчёт: `docs(review): add review report for <ветка>`. Каждый раунд дописывается в тот же файл.

## Чего не делать
- Не переписывай отчёт ревьюера своими словами и не удаляй из него замечания.
- Не проводи ревью сам в текущем контексте вместо субагента.
