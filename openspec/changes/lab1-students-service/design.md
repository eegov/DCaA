# Design

## Context

Новый проект. Требования в proposal.md и спецификациях. Лабы 2–7 добавят к этой системе сервис отчётов,
шлюз, RestTemplate, очередь и CompletableFuture, поэтому стек выбирается под всю серию.

## Goals / Non-Goals

**Goals:** минимальный сервис, который закрывает лабу 1 и который легко объяснить на защите.

**Non-Goals:** абстракции под будущие лабы, общий модуль для нескольких сервисов, кеширование.

## Decisions

- **Java 21 + Spring Boot 4.1.** В названиях следующих лаб прямо фигурируют `RestTemplate` и `CompletableFuture`
  из мира Java/Spring. Альтернатива ASP.NET Core тоже подходит, но для неё эти API пришлось бы подбирать по аналогии.
- **PostgreSQL 17.** Транзакции, ограничения уникальности и CHECK на уровне БД, официальный образ.
- **Liquibase в формате SQL.** Миграция читается как обычный DDL, rollback пишется рядом.
  XML/YAML-формат длиннее и не даёт выигрыша для одной таблицы.
- **Hibernate `ddl-auto: validate`.** Hibernate только сверяет сущность со схемой и падает при расхождении.
  Так схема живёт в одном месте (миграции), а ошибка в сущности видна при старте.
- **Идентификатор `BIGINT GENERATED ALWAYS AS IDENTITY`.** Короткие id удобнее при демонстрации в Swagger и pgAdmin,
  чем UUID. Сервис один, распределённой генерации ключей не требуется.
- **Курс 1–6** (бакалавриат 4 + магистратура 2) и статус `ACTIVE`/`EXPELLED` проверяются и в DTO, и CHECK-ограничением в БД.
  DTO даёт клиенту понятную ошибку 400, CHECK защищает данные от прямых SQL-изменений.
- **Отчисление статусом, удаление физически.** Отчисленный студент остаётся в учёте (понадобится отчёту в лабе 2),
  удаление нужно для полного CRUD и для записей, внесённых по ошибке.
- **Ошибки в формате ProblemDetail (RFC 9457)** через `ResponseEntityExceptionHandler`: стандартные ошибки Spring
  (405, 415, некорректный JSON) получают правильный статус без своего кода. Добавлены только 404, 409 и список полей для 400.
- **Docker Compose:** сервисы `db` и `app` в сети `students`; `app` в профиле `app`, чтобы локальный режим поднимал
  только БД. Порты публикуются на `127.0.0.1`. Данные БД в именованном volume.
- **Тесты:** `@SpringBootTest` + Testcontainers PostgreSQL. Те же миграции, та же СУБД, что в проде, поэтому
  тест на пустой БД одновременно проверяет Liquibase.

## Risks / Trade-offs

- [Два одновременных запроса с одним номером зачётки] → сервис проверяет уникальность заранее, а последнее слово
  за ограничением `uq_students_record_book`; проигравший запрос получит 500. Для учебного сервиса допустимо.
- [Тесты требуют Docker] → без Docker `./mvnw verify` падает явно, а не пропускает тесты.
- [Spring Boot тяжелее минимального сервиса] → окупается в лабах 2–7.
